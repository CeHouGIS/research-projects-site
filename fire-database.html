05 / Continuous geospatial infrastructure

Fire Database / GeoLakebase

把火灾边界、建筑物、卫星影像、现场损毁标签和模型预测组织成可版本化、可追溯的数据库与分析系统，并研究受约束的 LLM agent 如何监督异步数据流程。

当前状态系统运行与数据持续建设
核心系统DuckDB Spatial / FastAPI / MapLibre
源码GeoLakebase（私有）

研究问题

野火损毁评估不只是一个分类器问题。火灾边界、建筑清单、影像、现场标签和模型预测会以不同速度更新，系统需要知道哪些输入版本已经就绪、哪些结果可验证，以及何时允许写回数据库。

系统组成

  • DuckDB + spatial 统一 fires、buildings、damage labels、building footprints 和 PlanetScope scene metadata。
  • USGS、CAL FIRE DINS、xView2 等多源标签映射到统一 0–4 damage ontology，并保留原始标签和 provenance。
  • FastAPI 提供 fires、buildings、imagery、footprints、models 和 analysis 路由；MapLibre 网页提供地图与图层分析。
  • 模型、数据集版本、推理运行和写回结果进入 registry，支持审计输入、输出和源代码提交。

配套论文

`WildfireDB` 论文提出由 LLM agent 负责受约束的流程监督，由确定性的地理处理、模型推理、验证和数据库事务执行实际操作。

当前进度

  • 数据库 schema、数据摄取、跨源关联、ML 集成、REST API、网页和论文分析框架已经形成。
  • 数据快照中仍有 438 个 pending fires、13 个 completed、7 个 downloading 和 3 个 no-scenes，数据流水线仍在更新。
  • agent 机制已有仿真评估和运行日志审计，但 live LLM shadow-mode 或生产授权评估仍待开展。
这个项目已经从数据库原型进入“可运行系统 + 方法论文 + 公共网页”阶段；后续重点是补齐数据、验证写回流程和完成论文。
